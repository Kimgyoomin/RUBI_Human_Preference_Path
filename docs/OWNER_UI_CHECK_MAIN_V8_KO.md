# 본 조사 저장 대상으로 최종 UI 점검하기

## 승인된 범위
사용자가 새 시트로 전환한 뒤 직접 몇 문항을 답하며 최종 UI를 점검하기로 승인했다. 일반 참가자 모집 개시는 아니다. 질문·영상·로봇·제어기·카메라·16문항 규칙은 변경하지 않는다.

## 현재 배포 설정
- `public/study.json`: `rubi-hpp-main-v1`, `status=released`, `datasetTag=main-v1`.
- `collectionPhase=owner-ui-check-v1`을 추가한다. 이는 데이터 목적 표시이며 관리자 인증이나 서버 개방 권한이 아니다.
- 원래 파일럿 설정은 `config/study.pilot.json`에 보존한다. 기존 파일럿 응답은 기존 시트에 그대로 남는다.
- 일반 모집용 준비 설정은 `config/study.main.json`에 있으며, 이번 UI 점검 단계와 구분한다.
- 본 조사 대상: https://docs.google.com/spreadsheets/d/1Az6wHrRmSTjS6PeUjm2dzwI406Hnd0fyYj_JzkYdg-4/edit

## 최종 점검 기록 제외 규칙
이 단계에서 새로 만드는 `sessionId`는 `ui-check-<UUID>`이다. 화면에 점검임과 해당 ID를 표시한다. 기존 수집기는 `sessionId`를 Trials/Runs/Sessions에 저장하므로 Apps Script를 다시 수정할 필요가 없다.

본 조사 분석에서는 **`sessionId`가 `ui-check-`로 시작하는 모든 행을 제외**한다. 해당 세션의 Trials/Runs/Sessions 원본은 삭제하지 않고 보존한다. `participantId` 전체를 제외하는 것이 아니라 점검 세션을 기준으로 구분한다. `isPractice=false`는 정해진 본 문항 형식을 사용했다는 뜻이며, 분석 포함을 의미하지 않는다.

새로고침은 같은 점검 세션을 복원한다. 재시작하면 새로운 점검 ID를 만든다. 점검용 로컬 저장 키는 일반 참여 저장 키와 분리해, 나중에 단계 설정을 바꿔도 시험 진행 상태를 본 조사 세션으로 이어받지 않게 한다.

## 수집 허용은 소유자가 직접 실행
수집기가 이미 `isolated-main-collector-v8`로 배포되어 있다면 추가 Code.gs 재배포는 필요 없다.

1. 기존 Apps Script 편집기를 연다.
2. `openMainCollection_` 함수를 선택해 한 번 실행한다.
3. 실행 로그의 `open:true`와 대상 본 조사 파일 ID를 확인한다.
4. 설문 페이지를 새로고침한다. 상단에 '최종 점검' 안내와 `ui-check-` ID가 보여야 한다.
5. 한 문항 제출 후 새 시트에 Trials 1행, Runs 2행, Sessions 1행 및 사전 경험이 연결됐는지 확인한다. 몇 문항에서 멈춰도 저장된 원본은 유지하며 세션은 `started`로 남는다.

이 설정은 공개 링크를 아는 사람에게 실제 쓰기 요청을 허용한다. 'owner-ui-check'라는 이름이 소유자 전용 로그인 기능을 제공하는 것은 아니다. 지금 링크를 일반 모집용으로 배포하지 않는다. 점검 중단은 편집기에서 `pauseMainCollection_`를 실행한다. 이미 처리 중인 요청을 취소하는 기능은 아니다.

공개 페이지나 URL 파라미터로 이 관리자 함수를 호출하지 않는다. 끝의 `_`를 없애거나 공개 RPC로 노출해서는 안 된다. 스크립트 속성을 변경하는 작업은 소유자 편집기에서만 수행한다.

## 검사
- 실제 공개 빌드의 연구자 모듈 제외와 URL/플래그 접근 차단을 유지한다.
- 배포용 study.json 자체를 사용하고, Google 저장 서비스만 메모리 모형으로 치환해 첫 문항·두 실행·세션 연결을 확인한다.
- 점검 ID, 닫힌 수집 거부, 닫힘 상태에서 재접속, 재개 시 같은 ID·진행 수 보존을 검사한다.
- 기존 8문항 UI 회귀는 `config/study.pilot.json`을 명시적으로 사용하며, 실제 본 조사 API로 테스트 데이터를 전송하지 않는다.
- 자동검사 중 Google 본 조사 시트에 임의 응답을 쓰지 않는다. 실제 쓰기 최종 확인은 사용자의 점검 세션에서 수행한다.

## 일반 모집 전
점검 응답을 확인한 뒤 `collectionPhase` 제거를 별도 승인·변경으로 처리한다. 테스트 제외 규칙은 계속 유지한다. 연구 안내·연락처·보관 및 철회 방침·기관 검토는 연구자가 확정한다. 기능검사 통과를 통계 타당성이나 연구 승인으로 표현하지 않는다.
