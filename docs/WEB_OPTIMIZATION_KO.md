# RUBI 웹 최적화 — 2026-09-21

## 적용 범위

원본 `public/models/rubi/`는 수정하지 않았습니다. 기본 웹사이트는 새 `public/models/rubi-web/`를 사용합니다. 시각 메시 7개만 경량화했고 XML, encoder/policy, 발 접촉 STL 2개는 원본과 바이트 단위로 같습니다. 물리 timestep 0.002초, 정책 0.01초, 관측/히스토리/PD와 경로 추종 계산은 그대로입니다.

PongBot-R2의 DPR=1, 그림자 비활성화, 메시 법선 재사용 방식을 참고했습니다. 해당 로봇의 제어기나 비동기 추론 스케줄을 RUBI에 복사하지 않았습니다. 법선은 MuJoCo의 별도 face-normal 인덱스까지 확인해서 사용합니다.

## 안전장치와 재현성

- SHA-256 검사를 제거하지 않았습니다. 호스팅 로더의 중복 File 변환·중복 hash만 제거했고, 정상 로딩에서는 각 파일을 한 번 검증합니다.
- 해시를 URL 버전에 포함해 캐시를 사용합니다. 해시 불일치 시 한 번 재다운로드하고 다시 검증합니다. 작은 manifest의 `no-cache`는 저장 금지가 아니라 재검증입니다.
- 성공 rollout만 같은 탭 안에서 캐시합니다. 로봇/정책 해시, 제어 프로파일, 높이/폭/길이, 명령속도, 경로 좌표, 실행 계약이 같아야 재사용합니다. 실패를 성공으로 바꾸지 않습니다.
- 캐시 사용 여부와 원본 rollout ID/계산시간을 기록합니다. 두 경로 시청 확인, 1× 재생, 동의, 성공 조건은 유지됩니다.
- `eq_active`의 bool 메모리 뷰 바인딩 오류는 공식 `mj_getState/mj_setState`로 우회했습니다. 기존의 지지 구속 해제 시점과 다른 equality 상태를 유지합니다.
- 실제 컴파일된 물리 파라미터는 원본과 같았고, 무제어 1,000 step 비교의 qpos 차이는 0이었습니다. 이것만으로 모든 보행/지형의 동등성을 입증한 것은 아닙니다.

## 사용법

사이트를 새로고침하면 웹용 모델이 자동으로 로드됩니다. STL/ONNX를 다시 올릴 필요는 없습니다. 연구자 화면의 `성능 측정 · web-v1`에서 실제 로딩/계산시간을 확인할 수 있습니다. 평지부터 검사하고 실행 기록을 export하세요.

로컬 실행은 저장소 루트에서 `npm ci`, `npm test`, `npm run dev`입니다. 경량 메시가 이미 커밋되어 있으므로 일반 실행에 Python 패키지는 필요하지 않습니다. 재생성이 필요할 때만 `WEB_OPTIMIZATION.md`의 pinned generator 명령을 사용합니다.

## 아직 검증하지 않은 것

단차 높이별 반복 성공률, 여러 OS/브라우저에서의 재현성, 충분한 표면/실루엣 유사성, 실제 로봇과의 대응, 공개 응답 API 배포는 별도 검증입니다. 메시 AABB 차이가 작다는 것은 전체 표면 오차 보증이 아닙니다. 현재 `study.json`은 계속 `draft`입니다. 이번 최적화를 본 설문 준비 완료로 해석하지 않습니다.
